# 多 Agent 协作项目复盘 — AI Inspiration Notebook

> 本文档记录项目过程中踩过的坑、形成的协作模式、以及 Essie 的个人偏好。  
> 用途：新项目启动时，将此文档发给所有 Agent，他们应能快速理解各自的角色和工作流。

---

## 1. 项目概况

**项目**：AI 灵感簿（AI Inspiration Notebook）  
**角色**：Essie Zhang（产品经理 / 用户）  
**目标**：隔天从 GitHub、YouTube 等平台自动采集 AI 小项目，AI 筛选优先级，产品思维框架拆解，生成静态网页供翻阅学习  
**周期**：2026-06-20 至今  

---

## 2. Agent 角色分工

| 角色 | 职责 | 特点 |
|------|------|------|
| **产品经理** | 定义需求、维护 PRD、审批入库、验收产出 | Essie 本人 + PM Agent 辅助。PM Agent 负责定位 bug、写需求、派发任务，不写代码 |
| **产品研发** | 实现功能、修 bug、生成页面、维护脚本 | 接收 PM 的 REQ 任务，完成后回报验收 |
| **采集 Agent** | 运行采集脚本、AI 初筛、产出候选清单、通知 PM | 独立线程，可设置自动化定时触发 |

**关键原则**：PM 只做"发现 bug → 定位根因 → 写成明确 REQ → 派给研发"这条链路，不自己动手改代码。

---

## 3. 工作流

```
采集 Agent（隔天自动触发 / 手动触发）
    ↓ 产出候选清单 → 通知 PM
产品经理（审批候选项目）
    ↓ 确认入选 → 通知研发
产品研发（写入 projects.json + 生成页面 + 备份）
    ↓ 回报 PM
产品经理（验收）
    ↓ 有问题 → 退回研发修改
    ↓ 无问题 → 🎉 验收通过
```

## 4. 消息协议（跨 Agent 通信）

| 格式 | 用途 |
|------|------|
| `📋 REQ-YYYYMMDD-NNN` | 派发任务 |
| `✅ REQ-YYYYMMDD-NNN 完成` | 研发回报 |
| `⚠️ REQ-YYYYMMDD-NNN 验收未通过` | PM 退回 |
| `🎉 REQ-YYYYMMDD-NNN 验收通过` | 验收确认 |

每条消息携带 `request_id`、简述、相关文件路径、操作记录路径。

## 5. 踩过的坑 🔴

### 5.1 中文编码丢失（最严重的 bug）
- **现象**：页面卡片中文全部变成问号或乱码
- **根因**：PM 侧用 node 内联字符串写入 data 文件时，中文在 stdin 管道里丢失了编码
- **教训**：PM 绝对禁止直接修改 `projects.json` 和 `index.html`。所有数据写入由研发通过已验证 UTF-8 安全的脚本执行
- **排查路径**：先查数据源 → 坏了从 backup 恢复；数据源正常则生成脚本有问题

### 5.2 研发和 PM 互相踩脚
- **现象**：研发修完功能 → 页面中文乱码。PM 修完乱码 → 功能回退
- **根因**：两方都在改同一个文件（index.html），来源不同（研发跑脚本生成 / PM 手动覆写）
- **教训**：产出文件只有一个入口。index.html 只能由 generate_page.js 生成，任何人不得手动改

### 5.3 数据规范不一致
- **现象**：后 8 条项目的 category 用大写（Extensions），前 11 条用小写（chrome-extension），导致筛选和标签失控
- **教训**：数据写入标准要明确，所有 Agent 遵守同一个 schema。大小写、字段名、值域都要统一

### 5.4 采集 Agent 没有 send_message_to_thread
- **现象**：采集 Agent 完成任务后无法通知 PM
- **根因**：独立线程需要在 Codex 侧边栏创建（用户拥有的线程），不是 spawn 出来的子 Agent
- **教训**：需要跨线程通信的 Agent → 用户手动创建独立线程。不需要主动通知的临时任务 → spawn 子 Agent

## 6. Essie 个人偏好 💡

### 沟通风格
- **直接、简洁**：不需要冗长解释，要结论和下一步
- **非技术人员**：避免技术黑话，用产品语言描述问题和需求
- **决策快**：给选项时推荐一个并说理由，不用反复确认

### 产品审美
- **卡片内容**：语言平实、直白、简约但有信息量。不要夸张化的命令式语气，不要 VC/PPT 黑话
- **分析框架**：5 块（一句话 · Pain Point · Why AI · Product Insight · Transfer），重点是讲"为什么"而不是"是什么"
- **视觉**：暖色调莫兰迪风格，克制不花哨，字号偏小更舒适

### 项目理念
- **简单优先**：方案越简单越好，不需要为未来过度设计
- **适合个人长期维护**：一个文件能解决的不要拆成五个
- **质量 > 数量**：每天 5-10 条精选项目比 50 条泛泛的更有价值

## 7. 启动新项目的 Checklist

- [ ] 在根目录创建 `AGENTS.md`（Agent 协作协议）
- [ ] 创建 `_system/通信录.md`（线程 ID 注册表）
- [ ] 定义 PRD 文档位置和格式
- [ ] 设立 `PROJECT_RULES.md`（数据写入禁令等硬规则）
- [ ] PM Agent 只查 bug、写 REQ、派发任务，不改代码
- [ ] 研发 Agent 是唯一的代码 + 数据写入方
- [ ] 所有可执行脚本统一用 Node.js（避免 Python 编码坑）
- [ ] 设立数据备份机制（每次写入自动备份）
- [ ] 跨线程通信用 `send_message_to_thread`，不用 spawn 子 Agent
